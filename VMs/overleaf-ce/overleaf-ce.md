# Overleaf CE

## Overview
Overleaf Community Edition (self-hosted LaTeX editor) runs inside Docker on a VM created via the community Docker VM helper script. Deployment uses the official **Overleaf Toolkit** (Docker Compose based) and is exposed to the internet through a Cloudflare quick tunnel (cloudflared).

## Hardware
- **CPU:** 4 cores
- **RAM:** 4 GB
- **Storage:** 40 GB SSD
- **OS:** Ubuntu Server (from community `docker-vm.sh` helper script)

## Network
- **IP:** 192.168.1.203
- **Service Ports:** Overleaf on 80 (localhost-only behind tunnel)
- **Public Access:** Cloudflare quick tunnel (`*.trycloudflare.com`)

## Prerequisites
- Proxmox VE with internet access
- Community scripts repository accessible
- Cloudflare account (not required for quick tunnels, but recommended for a permanent tunnel)

## Deployment
1. Create the Docker VM on the Proxmox node:
   ```bash
   bash -c "$(wget -qLO - https://github.com/community-scripts/ProxmoxVE/raw/main/vm/docker-vm.sh)"
   ```
2. Start the VM, SSH into it, and create the Overleaf directory:
   ```bash
   mkdir ~/overleaf && cd ~/overleaf
   ```
3. Clone the Overleaf Toolkit:
   ```bash
   git clone https://github.com/overleaf/toolkit.git .
   ```
4. Initialize the toolkit configuration:
   ```bash
   bin/init
   ```
5. Install cloudflared:
   ```bash
   wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
   dpkg -i cloudflared-linux-amd64.deb
   ```
6. Start the Cloudflare quick tunnel (must be re-run after every container restart):
   ```bash
   nohup cloudflared tunnel --url http://localhost:80 > tunnel.log 2>&1 &
   ```
7. Extract the generated public URL from the log:
   ```bash
   grep -o 'https://[a-zA-Z0-9-]*\.trycloudflare\.com' tunnel.log
   ```
8. Point Overleaf at that URL:
   ```bash
   nano config/variables.env
   ```
   Update `SHARELATEX_SITE_URL` with the URL from step 7.
9. Restart the stack:
   ```bash
   bin/down && bin/up -d
   ```
10. Create an admin user:
    ```bash
    bin/docker-compose exec sharelatex npx grunt user:create-admin --email=example@email.com
    ```
11. Install extra LaTeX packages (e.g., a font scheme):
    ```bash
    bin/docker-compose exec sharelatex tlmgr install scheme-medium
    ```

## Configuration
- **Toolkit config:** `~/overleaf/config/variables.env` (site URL, TLS, MongoDB/Redis options)
- **Persistent data:** Docker volumes (`mongo_data`, `redis_data`, `sharelatex_data`) — configs in `config/`
- **Tunnel:** Quick tunnel URL changes on every restart; update `SHARELATEX_SITE_URL` and restart the stack each time (see Notes)

### Tunnel Restart Script
[`restart-tunnel.sh`](restart-tunnel.sh) (deployed at `~/overleaf/restart-tunnel.sh`) automates the full tunnel-refresh cycle — replaces steps 6–9 above when re-starting the stack:
1. Kills any stale `cloudflared` process.
2. Starts a new quick tunnel and truncates `tunnel.log`.
3. Extracts the new `trycloudflare.com` URL from the log (fails fast with an error if not found).
4. Updates `OVERLEAF_SITE_URL` / `SHARELATEX_SITE_URL` in `config/variables.env` via `sed`.
5. Restarts the stack (`bin/down && bin/up -d`) and prints the new URL.

Run it from the toolkit root after every container/VM restart:
```bash
cd ~/overleaf && ./restart-tunnel.sh
```

## Post-Install
- Access Overleaf via the tunnel URL and log in with the admin account (password set on first visit via the link generated by `user:create-admin`).
- After any restart, refresh the tunnel and URL with `./restart-tunnel.sh` instead of repeating steps 6–9 manually.
- Install additional LaTeX packages with `tlmgr install <package>` as needed.
- Back up the toolkit directory (`~/overleaf`) and Docker volumes regularly.
- Consider replacing the quick tunnel with a **named Cloudflare tunnel** (or NPM reverse proxy) for a stable, permanent URL.

## Notes
- The quick tunnel (`trycloudflare.com`) is **ephemeral**: every time `cloudflared` restarts, Cloudflare assigns a new random URL. Use the [`restart-tunnel.sh`](restart-tunnel.sh) script (see Configuration) after every container/VM restart instead of performing steps 6–9 manually.
- The original `tteck/Proxmox` scripts are deprecated; use `community-scripts/ProxmoxVE` (maintenance taken over by the community).
- Admin user creation prints a one-time password reset URL into the admin's email (or console); use it before logging in.
- `tlmgr` installs are not persistent across major image upgrades; re-run after pulling a new Overleaf version.
- Exposing to internet: the quick tunnel is fine for testing, but for production use a named Cloudflare Tunnel with proper auth, or route through NPM on the Docker Server.
